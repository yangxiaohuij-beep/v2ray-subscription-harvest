## 1. 代码结构

```
scripts/
  harvest_lite.py      1184 行  采集流水线（search/collect/prove/write）+ 打分 + bundles
  rebuild_bundles.py    150 行  用 subs/all.txt 重建 bundles（增量模式的补丁）
  make_v2rayn.py        183 行  bundles → v2rayN 三件套
  fetch_freev2rayu.py   289 行  附加源（静态站）抓取与探测
  run_daily.sh          118 行  日跑/全量编排 + 失败隔离 + 摘要
  run_full.sh            32 行  全量后台启动器（nohup）
```

依赖关系（只允许单向）：

```
run_daily.sh ──▶ harvest_lite.py ──▶ (标准库)
    │                ▲
    ├──▶ rebuild_bundles.py ── import harvest_lite（复用 classify/parse_endpoint/write_bundles）
    ├──▶ make_v2rayn.py     ── import harvest_lite.parse_endpoint
    └──▶ fetch_freev2rayu.py（自包含，只共享“协议白名单”语义）
```

**约定**
- Python ≥ 3.9，**零第三方依赖**（`urllib` / `socket` / `json` / `concurrent.futures`）。
- 所有时间戳为 UTC ISO8601（`now_iso()`），对外展示用本地时间。
- 所有 HTTP 都是「永不抛异常」风格：失败返回 `None` 或 `Response`，由调用方分类。
- 日志统一走 `log()`（写 stderr），便于与 stdout 摘要分离。

## 2. harvest_lite.py

### 2.1 关键常量

| 常量 | 值 | 含义 |
|---|---|---|
| `PROBE_BYTES` | 64×1024 | 每个链接只读前 64KB（公平口径，避免大文件拖慢） |
| `MAX_STALE_DAYS` | 12 | 退役窗口（运行时用 `--max-stale-days 14` 放宽） |
| `SUB_WEIGHTS` | reach .34 / fresh .20 / clean .14 / speed .12 / volume .12 / modern .08 | 打分权重 |
| `MODERN_MARKERS` | `reality`、`security=tls`、`hysteria2://`、`hy2://`、`tuic://`、`xtls`、`vless://`、`grpc`、`ws` | 现代协议标记 |
| `BUNDLE_PROTOCOLS` | vless / vmess / trojan / shadowsocks(ss,ssr) / hysteria2(hy2,hysteria) / tuic / wireguard(warp) | 按协议分包 |
| `BUNDLE_SIZES` | mini 100 / lite 300 / medium 1000 | 分档包 |

### 2.2 CLI

```
harvest_lite.py {search|collect|prove|write|run|daily} [选项]

公共:   --workers(16) --timeout(25) --probe-bytes(65536) --max-stale-days(12) --limit(0)
search: --query(可重复) --pages(2)
collect:--refresh --no-guess --retired-days(30) --tree --tree-budget(50)
prove:  --only-new --no-recurse --samples(12) --probe-workers(64) --tcp-timeout(3.0)
        --per-source(600) --max-new(0) --no-bundles
write:  --min-configs(5)
daily:  search+collect+prove+write（生产入口）
```

生产日跑实际使用：`daily --workers 40 --timeout 8 --tcp-timeout 2 --max-stale-days 14 --no-guess --no-recurse --only-new --max-new 600 --retired-days 30`（全量模式去掉 `--only-new` 与 `--max-new`）。

### 2.3 阶段一 search

```python
DEFAULT_QUERIES = ["v2ray config", "v2ray subscription", "vless subscription",
                   "free v2ray configs", "xray config collector", "v2ray-configs",
                   "vmess subscription", "v2ray collector telegram",
                   "free vpn configs vless", "sing-box subscription free",
                   "hysteria2 subscription", "reality config free"]
```

- 每词每页 100 条，`sort=updated`；页间 sleep：认证 2.5s / 未认证 7s；403 → 60s 重试。
- 新仓库按小写去重追加进 `rapo.txt`，保持只增不减。
- 完成标志：日志 `N new repositories added to rapo.txt` + `M repositories in rapo.txt`。

### 2.4 阶段二 collect

按优先级降级，命中即停：

1. **README**：`raw.githubusercontent.com/<repo>/HEAD/<name>`，name 依次 `README.md / README.MD / readme.md / Readme.md / README / README.txt / README.rst`；缓存到 `.cache/readme/<owner>__<repo>.md`。
2. **常见路径猜测**（`--no-guess` 可关）：对 `COMMON_PATHS` 逐个 HEAD 式 GET（`Range: bytes=0-4095`），2xx/206 且非空即命中。
3. **文件树扫描**（`--tree`，默认关）：`/repos/<repo>/git/trees/{HEAD|main|master}?recursive=1`，按 `--tree-budget` 限次；blob 需满足：`.txt` 或无扩展名、排除 readme/license/requirements/.github、路径含 hints（sub/config/all/mix/vless/vmess/trojan/shadowsocks/ss/hysteria/hy2/tuic/reality/merged/output/result/server）、按 (深度, 长度) 浅层优先取前 40。

链接规范化 `normalize_url()`（顺序敏感）：

```
1 去首尾空白 + 剥离尾部标点 .,;:!?'"\`)]}>*_
2 只接受 http(s)；含 <>{} 或 your_username / your_repository 的整条丢弃
3 github.com/.../blob/  → raw.githubusercontent.com/...（去掉 /blob/）
  github.com/.../raw/   → raw.githubusercontent.com/...
4 cdn.jsdelivr.net/gh/user/repo@ref/path → raw.githubusercontent.com/user/repo/ref/path
5 去掉 ?raw=true
```

预过滤 `is_plausible_sub()`：死域名（shields.io / t.me / twitter / youtube / discord / reddit / 各类文档站）、媒体与代码后缀、噪声路径（`/blob/`、`/tree/`、`/issues`、`requirements.txt`、`.github/`）、层级 ≤4 的 GitHub 仓库首页。

输出 `subs/candidates.txt`：每行 `url\trepo`，且**历史候选必须保留**（它们每天都要重证，否则会被退役规则误杀）。

写盘前还会做一次「退役过滤」：`--retired-days 30`（默认开启）把 `retired.txt` 里 **最近 30 天内退役** 的 URL 从候选池剔除。
原因：`write` 阶段退役时会把这些记录从 `status.json` 里移除，第二天 collect 又从 README 里把同一个 URL 收回来、
因为 status 里没有 → 被当成「新链接」重新证一遍，形成死循环（2026-11-26 候选池从 4.9k 涨到 8.3k、当日任务超时的直接原因）。
超过 30 天窗口后仍允许回归复评。实测：该过滤器上线首日即从候选池扣掉一批反复重证的退役源。

### 2.5 阶段三 prove

对每个 pending 链接执行 `check()`：

```python
verdict = classify(http_get(url, max_bytes=PROBE_BYTES, timeout=timeout))
if verdict.kind == "configs":
    endpoints = endpoints_of(verdict.body)          # 去重、最多 400 个
    sample    = random.sample(endpoints, min(len, --samples))   # 默认 12
    verdict.markers = sum(现代标记出现次数)
    verdict.uris    = CONFIG_URI_RE.findall(body)[:--per-source]
    verdict.body    = ""                            # 释放内存
```

分类判定顺序（**不可调换**）：

| 顺序 | 条件 | kind |
|---|---|---|
| 1 | 无响应 | `dead` |
| 2 | HTTP 非 2xx 且非 206 | `dead`（记 httpStatus） |
| 3 | body 空白 | `empty` |
| 4 | 前 2000 字符含 `<html`/`<!doctype html` | `html` |
| 5 | 配置 URI 数 **≥ 2**（直接数；为 0 时再试 base64 解码后数） | `configs` |
| 6 | 匹配 `^\s*proxies:` 或含 `proxy-groups:` | `clash` |
| 7 | 提取出的链接数 **≥ 3** | `catalog` |
| 8 | 其他 | `other` |

base64 识别 `try_base64()`：去空白 → 长度 ≥ 64 → 字符集限 `[A-Za-z0-9+/=_-]` → **截尾到 4 的倍数**再解（`b64decode` 与 `urlsafe_b64decode` 都试）。截尾只丢最后一条配置，比补 `=` 解出乱码安全。

端点解析 `parse_endpoint()`：

| 形态 | 处理 |
|---|---|
| `vmess://` | base64 → JSON，取 `add`/`host` + `port` |
| `ssr://` | base64，冒号分段取 host:port |
| `ss://` 无 `@` | base64 取 host:port |
| 其他 | `[userinfo@]host:port`，支持 `[v6]:port`；host 需匹配 `^[A-Za-z0-9._-]+$`，port 1–65535 |

TCP 探测：`tcp_latency()` 用 `socket.create_connection(timeout=--tcp-timeout)`，64 线程池，结果顺序汇总以保证可复现。

**新链接上限**：`--max-new N`（默认 0 = 不限）把本轮 pending 截断到 N 条，其余留到后续运行消化。
生产日跑设为 **600**：即使候选池突然暴涨（2026-11-26 有 3411 条待证），单轮证明量也是可预期的，
不会把调度器 3600 秒硬超时顶穿。全量模式不设上限。

记录写入 `status.json`（见 §9）。catalog 递归一层：新链接（不在 origin 也不在 status）再证一轮，`repo` 记 `(catalog)`。

### 2.6 阶段四 write

```python
for record in links.values():
    if record["kind"] == "configs": record["score"] = score_sub(record)
retired = prune_stale(links, alive_key="lastAlive", change_key="lastChanged", max_days=--max-stale-days)
alive   = [ (url,r) for url,r in links.items() if r["kind"]=="configs" and r["configs"] >= --min-configs ]
alive.sort(key=lambda kv: -kv[1]["score"])
写 all.txt（注释头 + 每行一个 URL）
```

退役规则：`firstSeen` 起已观测 ≥ max_days 天，且 `lastAlive` 为空或超过 max_days 天 → 移入 `retired.txt`（原因 `no configs for Nd` / `never alive` / `unchanged for Nd`），**从 status.json 中移除记录**但保留 retired 行，源回归会被当作新源重新评估。

### 2.7 打分算法（口径必须逐字一致）

```
score = 100 × ( 0.34·reach + 0.20·fresh + 0.14·clean + 0.12·speed + 0.12·volume + 0.08·modern )

reach  = reachRatio                        # 抽样端点中 TCP 握手成功占比
fresh  = freshness(days_since(lastChanged))
         days ≤ 1 → 1.0；days ≥ 12 → 0.0；其间 1 − (days−1)/(12−1)；从未变更 → 0.5
speed  = ≤60ms → 1.0；≥2000ms → 0.0；其间 1 − ln(ms/60)/ln(2000/60)   ← 对数，不是线性
volume = min(1, log10(1+configs) / log10(301))                         ← 300 条封顶
clean  = 0.5·min(1, 去重端点数/配置数) + 0.5·(各端点在所有源中出现份额的倒数均值)
modern = min(1, 现代标记出现次数 / 配置数)
```

结果与分项都落盘（`score`、`scoreParts`），因此**改权重后不必重新抓取**，重跑 write 即可。

## 3. HTTP 基础层

### 3.1 镜像回退（国内 raw 不可达）

```python
GH_MIRRORS = ["https://gh-proxy.com/", "https://ghproxy.net/", "https://ghfast.top/",
              "https://cdn.jsdelivr.net/gh/"]   # jsdelivr 形态单独拼接
```

- 只对 `raw.githubusercontent.com` 生效；候选顺序 = `[已记住的可用镜像] + 其余镜像 + 直连`。
- 首次成功的镜像记住并排到队首；返回 `None` 或 5xx 的镜像**本次会话拉黑**。
- 返回值里的 `url` 仍是原始地址，保证 `status.json` / `candidates.txt` 口径不变。
- 实测：单次 README 抓取 19.7s（直连偶发命中）→ 1.0s（稳定走镜像）。

### 3.2 代理探测（macOS 系统代理陷阱）

```python
def _proxy_works() -> bool:
    if os.environ.get("HARVEST_NO_PROXY"): return False
    try:
        urllib.request.build_opener().open(Request("https://api.github.com/"), timeout=4)
        return True
    except Exception:
        return False

_OPENER = build_opener() if _proxy_works() else build_opener(ProxyHandler({}))
```

原因：`urllib` 在 macOS 会读系统代理（`_scproxy`）。若代理进程活着但**节点已死**，CONNECT 会先回 200 再立刻断开，
表现为 `EOF occurred in violation of protocol`，而 `curl` 只读环境变量、不看系统代理，于是「curl 通、Python 全挂」。
`harvest_lite.py` 与 `fetch_freev2rayu.py` 都已内置该探测；`HARVEST_NO_PROXY=1` 可强制直连。

## 4. bundles 生成（write_bundles）

```python
for url, verdict, ... in results_sorted_by_source_score:
    for uri in verdict.uris:
        ep = parse_endpoint(uri)
        if ep is None or ep in seen: continue      # 端点全局去重
        seen.add(ep); ranked.append((score, scheme, uri))

publish("all", 全部)
publish("mini"/"lite"/"medium", 前 100/300/1000)
publish(按协议)  publish("reality", URI 含 reality)  publish("tls", URI 含 tls)
publish("best", score ≥ 85 的前 2000 条)
写 index.txt（包名 → 配置数）
```

- 每个包同时写 `<name>.txt`（带 `# format: v1` 头）与 `<name>-base64.txt`（纯 base64 单行）。
- **端点去重是核心**：同一 `host:port` 只保留来自最高分源的那一条，包内行数 == 端点数。

## 5. rebuild_bundles.py（增量模式的关键补丁）

### 5.1 为什么需要

`daily --only-new` 只重证新链接，`write_bundles()` 手里只有本轮证到的配置。
2026-10-31 实测：50 个待证链接 → 1 个带配置 → **bundles 只有 70 条配置**（而上一次全量是 64260 条）。
而 `make_v2rayn.py` 读 `bundles/best.txt`，该文件本轮未被重写 → **当日包与昨日 md5 完全相同**（文件名新、内容旧）。

### 5.2 做法

```
读 subs/all.txt（分数降序、跳过 # 注释）
  → ThreadPoolExecutor(40) 抓每个源（timeout 8s、单源最多读 512KB、最多取 400 条配置）
  → classify 只留 kind == configs
  → 端点去重计数
  → 唯一端点 < --min-total(500) ? 退出码 3，不写文件（保护）
  → 否则按 status.json 里的 score 排序，调用 harvest_lite.write_bundles() 重写 bundles/
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--workers` | 40 | 并发抓取数 |
| `--timeout` | 8 | 单源超时（秒） |
| `--per-source` | 400 | 单源最多取多少条配置 |
| `--max-bytes` | 524288 | 单源最多读多少字节 |
| `--min-total` | 500 | 唯一端点下限，低于则拒绝写入 |
| `--limit` | 0 | 只抓前 N 个源（调试/瘦身） |
| `--dry-run` | false | 只统计不写文件 |

**退出码**：0 成功；3 保护性放弃（保留旧 bundles）；1 参数/IO 错误。

实测（2026-11-01）：2804 源 → 2798 有配置 → **76400 唯一端点** → 87 秒 → 29 个文件。

## 6. make_v2rayn.py（交付格式转换）

```
读 bundles/best.txt  → 空则读 medium.txt → 再空读 all.txt
过滤假节点 is_fake_endpoint()：
  · 端点落在回环/内网/保留地址（127/8、10/8、192.168/16、172.16/12、169.254、0.0.0.0、::1、fc00::/7…）
  · 主机名命中 FAKE_HOSTS（localhost / example.com / your.server.com / ip / host …）
  · 解析失败不杀（交给客户端判断）
产出：
  v2rayN-<YYYYMMDD>-best.txt / -best-base64.txt
  v2rayN-<YYYYMMDD>-mini.txt / -mini-base64.txt
  v2rayN-<YYYYMMDD>-sources.txt   （来自 subs/all.txt 的订阅源 URL）
```

**mini 取样算法**（跨协议轮询 + 同主机限流）：

```python
buckets = 按 scheme 分组配置；order = 按组大小降序
循环：依次从每个协议组取一条，跳过 host 已达 per_host(2) 条的条目，直到凑满 100 条或无法推进
```

理由：上游 `mini.txt` 按来源分数取，若最高分源是单协议，100 条会被它一个占满，源一挂整包报废。
实测 2026-11-01 mini：ss 33 / vless 32 / trojan 32 / hysteria2 2 / vmess 1，覆盖约 100 个不同主机。

## 7. fetch_freev2rayu.py（附加源）

三步跟随，不硬编码日期：

```
首页 /free-nodes/  →  文章页列表（排除 page-\d+.htm）→ 取最新 N 篇（默认 2）
文章页  →  /uploads/<年>/<月>/<序号>-<YYYYMMDD>.txt（整段 base64，另有 .yaml 忽略、.json 常为 0 字节）
资源    →  base64 解码 → 协议白名单过滤 → 剔除内网/示例地址 → TCP 探测（2s / 32 并发）
产出    →  out/freev2rayu-<STAMP>.txt 与 -base64.txt
```

- `http_get()` 内置代理探测 + 直连回退 + **3 次重试**（2s / 5s 退避）。
- 失败只体现在 rc 与日志，**不改变 run_daily 退出码**，也不影响主包。
- 该站更新不频繁（2026-10-24~10-30 曾连续 404），所以「每日抓」实际是每日重测同一批节点的存活。

## 8. 编排脚本

### 8.1 run_daily.sh

```bash
RUN="${HARVEST_RUN_DIR:-$(dirname $0)}"    # 可搬迁
PY="${HARVEST_PYTHON:-/usr/bin/python3}"
GH="${HARVEST_GH:-/opt/homebrew/bin/gh}"
MODE=daily|full                             # full 时 EXTRA 为空、日志改名 full-*.log

1  取 token：TOK=$(gh auth token) → export GITHUB_TOKEN（只进环境变量，不落盘）
2  防重入：.lock 存在且 pid 存活 → 打印「跳过」并退出 0
3  harvest：           daily [--only-new]
4  if rc==0：rebuild_bundles → make_v2rayn     else：VRC=99、RRC=99（不导出）
5  fetch_freev2rayu（独立失败域）
6  摘要：各段 rc / 耗时 / 仓库数 / 候选数 / 存活源数 / 产物清单 / MEDIA 附件行
7  exit rc            # 采集失败时退出码非零，便于调度器标记
```

失败隔离矩阵：

| 环节 | 失败时 | VRC | RRC | 退出码 |
|---|---|---|---|---|
| harvest | 跳过重建+导出，写 `⚠️` | 99 | 99 | 非零 |
| rebuild | 保留旧 bundles，继续导出 | 正常 | 3 | 0 |
| make_v2rayn | 无当日包 | 非零 | 0 | 0 |
| freev2rayu | 少一个补充包 | 0 | 0 | 0 |

### 8.2 run_full.sh

检查 `.lock` → `cd $RUN` → `nohup env MODE=full ./run_daily.sh > logs/full-nohup-<日期>.log &` → 打印 pid 立即返回。
目的：全量 16 分钟，同步执行有被定时器杀掉的风险（历史 rc=143 事故）。

## 9. 数据字典

### 9.1 `subs/status.json`

```json
{
  "generatedAt": "2026-11-01T00:03:52Z",
  "links": {
    "<source url>": {
      "firstSeen": "2026-10-26T15:45:50Z",
      "kind": "configs|dead|html|empty|other|catalog|clash",
      "configs": 128,               // 窗口内配置数
      "protocols": ["vless","ss"],
      "httpStatus": 200,
      "bytes": 65536,
      "lastChecked": "2026-11-01T00:03:38Z",
      "lastAlive": "2026-11-01T00:03:38Z",
      "lastChanged": "2026-10-31T23:05:10Z",
      "changes": 7,
      "digest": "9f3ac1d2b7e04f18",  // 解码后文本 sha256[:16]
      "sampled": 12, "reachRatio": 0.917,
      "medianLatencyMs": 88.4,
      "cleanRatio": 0.83, "modernRatio": 0.41,
      "scoreParts": {"reach":0.917,"fresh":1.0,"clean":0.83,"speed":0.72,"volume":0.86,"modern":0.41},
      "score": 86.42,
      "repo": "owner/repo"
    }
  }
}
```

### 9.2 文本文件

| 文件 | 格式 |
|---|---|
| `rapo.txt` | 每行 `https://github.com/owner/repo`（小写去重、只增） |
| `subs/candidates.txt` | 每行 `url\trepo`（repo 可为 `(catalog)`） |
| `subs/all.txt` | 注释头（`# format: v1`、计数、说明）+ 每行一个 URL，**分数降序** |
| `subs/retired.txt` | 每行 `ISO时间\t原因\turl` |
| `subs/bundles/index.txt` | `# Generated …` + 每个包 `<name>.txt  # N configs` |
| `out/v2rayN-<日期>-sources.txt` | 每行一个订阅源 URL（可直接配 v2rayN 订阅） |

## 10. 错误码

| 码 | 来源 | 含义 |
|---|---|---|
| 0 | 全部 | 成功 |
| 1 | harvest / rebuild / make_v2rayn | 参数或 IO 错误（如 bundles 目录不存在） |
| 3 | rebuild_bundles.py | 唯一端点 < `--min-total`，保护性放弃写入 |
| 99 | run_daily.sh | 上游失败导致的「跳过」占位（非真实进程退出码） |
| 130/143 | 任何 | 被 SIGINT/SIGTERM 终止（历史上曾被调度器超时杀掉） |

## 11. 参数总表（生产值 vs 默认值）

| 参数 | 默认 | 生产 | 影响 |
|---|---|---|---|
| `--workers` | 16 | 40 | 全量耗时的主要杠杆（16/25s → 9 小时；40/8s → 16 分钟） |
| `--timeout` | 25 | 8 | 同上；死链占比高时最敏感 |
| `--tcp-timeout` | 3.0 | 2 | 端点探测耗时 |
| `--samples` | 12 | 12 | 每源抽样数，越大 reachRatio 越准、越慢 |
| `--per-source` | 600 | 600 | 单源进入 bundles 的配置上限，防单源灌包 |
| `--max-stale-days` | 12 | 14 | 退役窗口；增量模式必须比「全量周期」更长 |
| `--min-configs` | 5 | 5 | 少于 5 条配置的源不进 `all.txt` |
| `--min-total`（rebuild） | 500 | 500 | 重建保护阈值 |
| `--max-new` | 0（不限） | **600** | 单轮最多证多少条新链接（防止候选暴涨顶穿 3600s 硬超时） |
| `--retired-days` | 30 | 30 | collect 时跳过多少天内退役的源（0=关闭） |

## 13. 测试与验证方法（本项目实际采用）

| 目的 | 方法 |
|---|---|
| 编排顺序正确 | 沙箱目录 + 桩 Python（记录 argv），断言调用顺序 `harvest→rebuild→export→free` |
| 失败隔离生效 | 桩返回 1，断言不调用 rebuild/export、摘要出现 `rc=99`、日志有跳过告警 |
| **当日包真伪** | `md5 out/v2rayN-<今日>-best.txt out/v2rayN-<昨日>-best.txt` 必须不同；`bundles/index.txt` 的 `Generated` 必须是今日 |
| 计数一致 | `grep -c "://"` 与脚本自报行数比对；`grep -vc '^#' all.txt` 与头部 `N links` 比对 |
| 分数可复现 | 任取 `status.json` 一条记录，按 §2.7 手算 `scoreParts` 与 `score`，误差 < 0.05 |
| 可移植性 | `HARVEST_RUN_DIR` / `HARVEST_PYTHON` 指向临时目录，脚本应能独立跑完 |
