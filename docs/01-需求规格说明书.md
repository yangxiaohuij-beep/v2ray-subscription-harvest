## 1. 背景

### 1.1 现状

免费代理节点（vless / vmess / trojan / ss 等）在中国大陆用户群体中的主要获取方式是「公开订阅源」：
一串指向 GitHub 仓库 raw 文件的 URL，客户端定时拉取后得到成千上万条配置。这些源有三个特征：

1. **极其分散**：单次 GitHub 搜索「v2ray subscription」即可命中上千个仓库，且每天新增。
2. **噪声极高**：实测候选链接中只有约 20% 真的返回配置；其余是死链、HTML 页面、README 文本、占位示例。
3. **生命周期短**：节点被墙、被判、被作者删库都很常见，一个源能稳定活过两周已是少数。

### 1.2 痛点

| 痛点 | 具体表现 |
|---|---|
| P1 发现成本 | 靠人肉收藏几十个频道/仓库，无法覆盖全量，且不知道哪些还活着 |
| P2 质量不可知 | 客户端拉回 5000 条，其中大部分是死节点，用户只能一条条点「测速」 |
| P3 单点依赖 | 只订阅一两个源，源一挂整个客户端报废 |
| P4 判断无依据 | 「哪个源更好」除了直觉没有可量化口径，换源像抽奖 |
| P5 更新不可持续 | 手工维护的订阅清单，主人不更新后就腐烂，逐步退化成死链集合 |

### 1.3 目标

用一个无人值守的自动化流水线，把「找源 → 验证 → 排序 → 打包 → 交付」变成每天自动发生的事，
并且**所有排序依据都是可测量、可复现的数字**，而不是主观印象。

## 2. 范围

### 2.1 范围内

- 从 GitHub 公开仓库自动发现订阅源链接；
- 对每个链接做抓取、分类、抽样 TCP 探测、打分；
- 输出按分数排序的订阅源清单（`subs/all.txt`）；
- 输出客户端可直接导入的节点包（v2rayN 格式，明文 + base64）；
- 输出一个独立的「附加源」（Free V2rayU 静态站）节点包；
- 每日增量 + 每周全量的调度编排、失败隔离与可观测性（日志/摘要）。

### 2.2 范围外（明确不做）

| 不做的事 | 原因 |
|---|---|
| 自建/运营节点或中转 | 本项目的价值在「筛选」，不在「供给」；自建另有合规与成本问题 |
| 流量转发、协议握手验证、TLS 指纹探测 | 成本高、对源站不友好；TCP 可达 + 抽样延迟已足够区分好坏 |
| 客户端 GUI | 直接复用 v2rayN 的导入能力，不做壳 |
| 节点分享/分发平台 | 只产出文件，不对外提供服务 |
| 账号体系、数据库服务端 | 纯本地流水线，状态用文件（JSON/文本）承载 |

## 3. 角色与使用场景

| 角色 | 关注点 | 典型动作 |
|---|---|---|
| **A. 终端用户**（主要） | 今天能不能用、别浪费我时间 | 每天拿 `best-base64` 导入 / 挂 `sources.txt` 做长期订阅 |
| **B. 运维者**（本机主人） | 任务有没有按时跑、挂了怎么修 | 看 cron 摘要、查日志、必要时手动补跑 |
| **C. 二次开发者** | 能不能改打分、加协议、换客户端 | 调权重、加 `BUNDLE_PROTOCOLS`、写新的 `make_*` 导出器 |

### 3.1 主要用例

- **UC-1 每日自动收割**：每天 07:00 自动完成一次增量收割 + 打包，产出当日包；用户醒来即可用。
- **UC-2 手动补跑**：任务失败/机器关机错过时，用户可一条命令补跑。
- **UC-3 深度刷新（全量）**：每周日凌晨对全部候选重新测一遍，修正增量模式的漂移。
- **UC-4 导入客户端**：用户把 base64 包粘进 v2rayN，或把 `sources.txt` 配成自动更新订阅。
- **UC-5 排障**：运维者根据摘要里的 `rc` 字段与日志尾部，5 分钟内定位失败环节。

## 4. 功能需求

> 编号规则：`FR-<阶段>-<序号>`。优先级：**M**=必须、**S**=应该、**C**=可选。

### 4.1 发现（search）

| 编号 | 需求 | 优先级 | 验收判据 |
|---|---|---|---|
| FR-D-01 | 用可配置的多组关键词调用 GitHub Search API 发现仓库 | M | 默认 12 组词 ×2 页，日志打印每组去重计数 |
| FR-D-02 | 仓库清单去重、按小写排序、增量追加，不丢历史 | M | 重跑不产生重复行；`rapo.txt` 行数只增不减 |
| FR-D-03 | 遵守 API 限流：认证 2.5s/页、未认证 7s/页，403 退避 60s | M | 连续多日运行无 403 中断 |
| FR-D-04 | 记录新增仓库明细（便于审计「今天多了哪些源」） | S | 日志列出新增 owner/repo |

### 4.2 收集（collect）

| 编号 | 需求 | 优先级 | 验收判据 |
|---|---|---|---|
| FR-C-01 | 抓取仓库 README（多种大小写/扩展名），本地缓存 | M | 二次运行命中缓存，网络请求显著减少 |
| FR-C-02 | 无 README 时按常见路径探测（命中即止） | S | 日志可区分「README 命中」与「路径探测命中」 |
| FR-C-03 | 可选的递归文件树扫描（受 API 预算约束） | C | 预算耗尽时输出 `tree budget spent` 而非报错 |
| FR-C-04 | 链接规范化：`blob→raw`、jsdelivr→raw、去 `?raw=true`、剥尾部标点 | M | 同一文件的不同写法在候选池中只出现一次 |
| FR-C-05 | 候选预过滤：死域名、媒体/代码后缀、噪声路径、仓库首页 | M | 明显无意义的候选不进入 prove 阶段 |
| FR-C-06 | 候选池每行 `url\trepo`，含历史候选（老链接必须每日重证） | M | `candidates.txt` 行数与日志一致 |

### 4.3 验证（prove）

| 编号 | 需求 | 优先级 | 验收判据 |
|---|---|---|---|
| FR-P-01 | 单链接抓取窗口 64KB、超时 8~25s、可配置并发 | M | 并发 40 时全量收敛在 20 分钟内 |
| FR-P-02 | 分类严格有序：dead → empty → html → configs(≥2) → clash → catalog(≥3) → other | M | 任取一条记录人工复核与日志判定一致 |
| FR-P-03 | base64 订阅自动识别（截尾到 4 的倍数再解码，两套字符集都试） | M | base64 源被判为 `configs` 且 note 标 `base64` |
| FR-P-04 | 端点解析覆盖 vmess/ssr/ss/普通 authority，IPv6 用 `[v6]:port` | M | 端点抽测数与日志 `probing N distinct servers` 一致 |
| FR-P-05 | 每链接抽样 12 个端点做 TCP 握手，记录延迟中位数 | M | `status.json` 有 `sampled` / `reachRatio` / `medianLatencyMs` |
| FR-P-06 | catalog 类链接递归一层（新链接也进入测量池） | S | 日志出现 `links found inside catalogs — proving those too` |
| FR-P-07 | 增量模式只证新链接（`--only-new`），全量模式重证全部 | M | 增量阶段耗时 < 4 分钟 |
| FR-P-08 | 单条链接失败不中断整批 | M | 大量死链场景下仍能跑完并产出结果 |

### 4.4 排序与退役（write）

| 编号 | 需求 | 优先级 | 验收判据 |
|---|---|---|---|
| FR-W-01 | 按六项权重打分（reach/fresh/clean/speed/volume/modern） | M | 任取一条记录手算与存储分数误差 < 0.05 |
| FR-W-02 | `subs/all.txt` 按分数降序、带完整注释头、计数与实际行数一致 | M | 头部写 `N links`，`grep -vc '^#'` 等于 N |
| FR-W-03 | 退役规则：观测满 14 天且期间无存活/无变更 → 移入 `retired.txt` | M | retired.txt 每行含日期、原因 |
| FR-W-04 | 退役只记录不删除，前科保留在 `status.json` | M | 源回归后能被重新评估并回到 all.txt |

### 4.5 打包（bundles / export）

| 编号 | 需求 | 优先级 | 验收判据 |
|---|---|---|---|
| FR-B-01 | 产出 all/mini/lite/medium、按协议、reality、tls、best 及各自 base64 | M | `index.txt` 列出的每个包都存在且计数一致 |
| FR-B-02 | 端点全局去重，同一 endpoint 只保留最高分来源的那一条 | M | 包内端点计数 == 行数 |
| FR-B-03 | best = 分数 ≥ 85 的源，上限 2000 条 | M | best 行数 ≤ 2000 |
| FR-B-04 | mini 跨协议轮询取样 + 同主机最多 2 条 | M | 100 条覆盖 ≥4 种协议、≈100 个不同主机 |
| FR-B-05 | 过滤占位/内网假节点（127.x、10.x、example.com、全零 UUID） | M | 导出日志有「已过滤 N 条」 |
| FR-B-06 | 导出 v2rayN 三件套：best / mini / sources（明文 + base64） | M | 文件名带当日日期，可被 v2rayN 直接导入 |
| FR-B-07 | **增量模式下，导出前必须用当日存活源重建 bundles** | M | 当日包 md5 ≠ 前一日；`bundles/index.txt` 的配置数与 `all.txt` 源数量级相称 |
| FR-B-08 | 重建结果太少（<500 唯一端点）时拒绝写入，保留旧包 | M | 返回码 3，`out/` 不被覆盖 |

### 4.6 附加源（Free V2rayU）

| 编号 | 需求 | 优先级 | 验收判据 |
|---|---|---|---|
| FR-A-01 | 独立抓取该站点：首页 → 最新 N 篇文章 → 文章内挂的 `.txt` 资源 | M | 日志打印文章日期与资源数 |
| FR-A-02 | base64 解码、协议白名单、剔除内网/示例地址 | M | 输出文件只含允许协议 |
| FR-A-03 | 重新做 TCP 探测，只留存活节点 | M | 日志 `TCP 存活 X/Y` |
| FR-A-04 | 产出独立文件，**不并入主 bundles** | M | `out/freev2rayu-*` 与 `subs/bundles/` 无交集 |
| FR-A-05 | 该源失败不影响主流程与退出码 | M | 摘要里单列 `rc`，主包照常产出 |

### 4.7 编排与可观测性

| 编号 | 需求 | 优先级 | 验收判据 |
|---|---|---|---|
| FR-O-01 | 一条命令完成日跑（搜索→收集→重证→写→重建→导出→附加源） | M | `./run_daily.sh` 可独立运行 |
| FR-O-02 | 全量启动器秒级返回，后台 nohup 运行 | M | `run_full.sh` 立即打印 pid 并退出 |
| FR-O-03 | 防重入：已有采集在跑时第二次调用直接退出 0 | M | `.lock` 存在且 pid 存活时打印「跳过」 |
| FR-O-04 | 失败隔离：采集失败不导出、附加源失败不影响主包 | M | 摘要中三项 `rc` 相互独立 |
| FR-O-05 | 摘要包含：各段 rc、耗时、仓库数、候选数、存活源数、产物清单 | M | 摘要可直接作为人读汇报 |
| FR-O-06 | 日志按日归档，保留可追溯的失败现场 | M | `logs/daily-YYYYMMDD.log`、`logs/full-*` |

### 4.8 网络适配（国内环境）

| 编号 | 需求 | 优先级 | 验收判据 |
|---|---|---|---|
| FR-N-01 | `raw.githubusercontent.com` 直连不可用时自动改走镜像（4 个，逐个回退） | M | 日志无长时间卡死；镜像坏掉后本次会话不再重试它 |
| FR-N-02 | 系统代理存在但实际不通时，自动改为直连 | M | 系统代理开启且节点失效时，采集仍能完成 |
| FR-N-03 | 瞬时 SSL/超时错误有重试（附加源脚本 3 次，2s/5s 退避） | S | 单次抖动不导致整包失败 |

## 6. 验收标准（整体）

一次交付被认为合格，当且仅当：

1. `./run_daily.sh` 在干净目录（6 个脚本 + 空 `subs/`）首次运行能建立 `rapo.txt` → `candidates.txt` → `subs/all.txt` → `bundles/` → `out/` 全链路产物；
2. 当日 `out/v2rayN-<今日>-best.txt` 行数 > 800，且 md5 与前一日不同；
3. base64 包粘贴进 v2rayN 能成功解析导入（人工验证 1 次）；
4. 人为制造失败（采集 rc≠0、附加源不可达、bundles 重建过少）时，摘要如实反映，且**不产出伪当日包**；
5. 全部产物与文档可从零复现（本文档 + 04 详细设计足以重建系统）。

## 7. 术语表

| 术语 | 含义 |
|---|---|
| 源（source） | 一个返回配置集合的 URL，通常指向 raw 文件 |
| 配置（config） | 单条 `vless://` / `vmess://` / `ss://` 等 URI |
| 端点（endpoint） | 配置实际拨号的 `host:port`，用于去重与 TCP 探测 |
| catalog | 「链接的链接」——页面里含有 ≥3 个订阅链接 |
| bundles | 本项目自己拼装的多档节点包（all/mini/…/best） |
| 增量 / 全量 | 只重证新链接 / 重新证全部候选 |
| 重建（rebuild） | 用 `all.txt` 的存活源重新抓配置并重写 bundles |
